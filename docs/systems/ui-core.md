# System: ui-core

Owner: builder-ui-core. Folder: `src/renderer/src/` (app frame, `screens/` for the screens below, `components/` shared, `styles/`). Research: `research/gamified-learning-platforms.md` section 1 for what each platform's screens do well; `research/tooling-and-stack.md` section 3.

## Visual direction

Use the frontend-design skill before the first screen. Dark, high contrast, generous type, one accent per pack (foundations amber, patterns violet, mechanics cyan, systems green), short feedback transitions (150 ms or less on hover, press, and panel open) allowed and expressive motion reserved for reward moments (A98), a small cast of studio characters drawn as simple vector portraits (client, lead programmer, QA) used sparingly for delight. No stock dashboard look, no gradients-on-everything. Tokens in `styles/tokens.css` (colors, spacing, radii, type scale, motion durations). Every screen works at 1100x700.

## Shared components

`TermText` (react-markdown with the TermLinker plugin, renders glossary terms as `HoverCard`), `HoverCard` (short definition, "Read more" opens the Codex panel, "Drill me" adds to the queue, increments hover count), `XpBar`, `RoleBadge`, `PatternCard` (front and back, tier frame), `SkillTree` (inline SVG, grouped by prefix, mastery color), `StreakFlame`, `SpreeMeter`, `QuestCard`, `Chest`, `AppError`, `KeyboardHints`.

## Screens

- Title: player name, continue, environment chips (engine found with version, sandbox ready, review provider active, loop mode). Fresh learner goes to First-run.
- First-run setup: pick engine (auto-detected list plus manual), pick sandbox folder (short path warning), full build progress with phase and elapsed, open editor once, done. Each step has a plain-English failure message and a retry.
- Studio home: avatar and role, engine room with modules earned, shipped-titles wall, today's daily quest offers (three), due drill count with a start button, streak and freezes, continue last quest, next due dates.
- World Map: packs as regions, worlds as contract cards with the client's one-paragraph brief, quests as stages on a path with states (locked with the reason on hover, available, in progress, passed, due for rematch glowing), boss as a larger node, test-out button per world when eligible.
- Character: level and role, XP bar, pattern card grid (locked silhouettes, tiers), skill tree with mastery, spree and best, streak and milestones, attempt history, Seer Stones and armor held.
- Codex: searchable glossary (Cmd/Ctrl+K), category filters, each entry with short, long, example, related, Epic docs link, "where you met it", "drill me".
- Settings: engine path, sandbox path, loop mode (auto, fast, headless), review provider with availability, API key (masked), model id, test Claude Code button, rebuild sandbox, reset progress with confirmation.

Keyboard: Cmd/Ctrl+K codex search; Esc closes panels.

## Done criteria

## Architecture (keep current)

Last updated by M2.1 fix round 1 (merged content contract, packaged guard, background refresh).

### Tokens
- `styles/tokens.css` is the only place colors, fonts, type scale, spacing, radii, shadows, easing, entrance animations, and motion durations are defined. They are Tailwind v4 theme variables (`@theme static`, so every one is emitted on `:root` even when no utility uses it), which makes each both a CSS variable (`var(--color-ink)`) and a utility (`bg-ink`, `text-paper-muted`, `w-rail`, `rounded-lg`). Tailwind's default palette, type scale, radii, and shadows are reset, so only Dojo tokens exist.
- Colors: surfaces `ink`, `surface`, `raised`, `overlay`, `line`, `line-strong`; text `paper`, `paper-muted`, `paper-faint`; outcomes `pass`, `fail`, `warn`; pack accents `foundations` (amber), `patterns` (violet), `mechanics` (cyan), `systems` (green), each with `-soft` (tinted fill) and `-deep` (text on the accent). The shadcn names (`background`, `primary`, `muted`, `border`, `ring`, ...) are aliases onto these.
- Current pack: `pack`, `pack-soft`, `pack-deep`, `ring`, and `shadow-glow` follow the nearest `data-pack="<pack id>"` attribute (an `@theme inline` block plus `[data-pack]` rules). Foundations amber is the default and the app's signature accent.
- Motion durations (`--duration-instant` to `--duration-reward`) are plain variables, used as `duration-(--duration-fast)`. Feedback uses `instant` or `fast` (150 ms or less); `base`, `slow`, and `reward` are for reward moments only (A98). They drop to zero under `prefers-reduced-motion`.
- Font licenses ship in the packaged app at `Resources/licenses/fonts/` through an electron-builder `extraResources` entry.
- Fonts are committed woff2 files in `assets/fonts/` with `fonts.css` (imported first by `styles/global.css`) and their OFL licenses: Bricolage Grotesque (`font-display`, headings), Instrument Sans (`font-sans`, body), JetBrains Mono (`font-mono`, code and keys). No network at runtime.
- `styles/tokenCatalog.ts` names every token and its purpose for the gallery; `tests/renderer/tokenCatalog.test.ts` fails if it and `tokens.css` drift.

### Frame and routing
- `App.tsx` renders `app/AppFrame.tsx`: the `NavigationRail` (brand mark, one `RailLink` per screen, Codex search button), a scrollable stage with the dot-grid background, and the overlay panels. The shared `TitleBarDragRegion` (36px, `.app-drag-region`, room for the macOS window buttons, interactive children stay clickable) is fixed across the top of both columns; each column starts with an empty `h-titlebar` band (48px) so nothing clickable sits under it.
- Routing is a hash router with no library: `app/router/routes.ts` (route table, `routeFromHash`, `hashForRoute`; pure, unit tested) and `app/router/useRoute.ts` (`useRoute` over `hashchange`, `useNavigate`). `app/ScreenOutlet.tsx` maps a route id to its screen. Routes: `#/` Title, `#/studio`, `#/world-map`, `#/character`, `#/codex`, `#/settings`, and, not in the rail, `#/first-run` and `#/dev/tokens` (gallery).
- Panels: `app/usePanelStore.ts` (Zustand) holds which overlays are open. `hooks/useGlobalShortcuts.ts` toggles Codex search on Cmd+K (macOS) or Ctrl+K and closes every panel on Esc. `components/CodexSearchPalette.tsx` searches the glossary (arrow keys, Enter opens the term on the Codex screen through `app/useCodexStore.ts`, which also holds the Codex category filter).
- Screens live in `screens/<Name>Screen.tsx`, each screen's parts in `screens/<feature>/` (`title/`, `firstRun/`, `studio/`, `worldMap/`, `character/`, `codex/`, `settings/`). The gallery is `screens/dev/`. The rail shows a "Fake data" badge while the fake data source is active.
- Base components in `components/ui/` (shadcn/ui on `radix-ui`, restyled): `button`, `badge`, `dialog`, `input`, `kbd`, `separator`, `tooltip`. File names follow shadcn; `dialog` and `tooltip` are compound components whose parts live in one file.
### Data layer (A240 to A242)
- No screen or component touches `window.dojo`. `main.tsx` awaits `data/activeClient.ts` `loadDojoClient()` before React mounts; it picks the data source with `data/dataSourceChoice.ts` (pure: in a packaged build always the real bridge, A251; otherwise `localStorage["dojo.dataSource"]` = `fake:<scenario>` wins, then the build flag `VITE_DOJO_FAKE`, else the real bridge) and exposes it as `dojo()`.
- `data/DojoClient.ts`: `DojoClient = DojoApi` (the content methods came with M0.2b; A241 is superseded). The real client is `window.dojo` itself.
- `data/QueryCache.ts` caches answers by key (`data/queryKeys.ts`), keeps the last answer visible while refreshing, and turns every rejection into an `AppError` (`data/toAppError.ts`). `observe(key, load)` counts the screens reading a key and fetches on every mount (in the background once cached); `refetchObserved()` refreshes what mounted screens read, called on window focus by `data/useRefetchOnFocus.ts` in the frame. Hooks: `useDojoQuery(key, load)` for reads; `useDojoAction(action, invalidates)` for changes, which refreshes the listed keys; `useBuildProgress(runId)` follows progress events; `useSandboxBuild(operation, context)` runs a create or rebuild through `data/SandboxBuildTracker.ts`, a recovery fallback (A822): it subscribes to progress before the call goes out, keeps its own elapsed clock, marks the build quiet after 15 s without new output and asks `getRunStatus` then and every 15 s after (each check times out after 10 s; 3 failures in a row mark main unreachable), counts a status as new output only when its `eventCount` is higher than the events seen, and applies the answer once from whichever arrives first, the call or a finished status. A run main no longer knows ends with a `run-not-found` error whose advice depends on the context (A824). `components/QuietBuildNotice.tsx` shows the quiet state ("No word", "Still running; no new output", or "cannot get an answer") with a Check status button on First-run and Settings.
- Rule constants (level curve, roles, caps, thresholds, milestones) reach screens only through `getRules`. `lib/levels.ts` turns XP into level and role from that snapshot.
- `data/fake/FakeDojoApi.ts` is a typed, in-memory `DojoClient` (a lazy chunk). Fixtures in `data/fake/fixtures/`: a four-pack map with every stage state whose first world mirrors the real Pack 1 World 1 (12 stages, real titles) (`mapFixture.ts`, outlines built by `questFactory.ts`), returning and fresh saves, rules matching M1.6, machine answers (engines, toolchain, sandbox folder, providers) shaped for the current OS. `SandboxBuildSimulator.ts` streams a believable first build (elapsed time scaled up) and fails once in the `first-build-fails` scenario. Glossary, its alias table, and pattern cards come from the real `content/*.json`. `createSandbox` remembers the sandbox path on a pass and nothing else, as the sandbox service does. Since M2.2 the quest-flow methods answer too (`FakeQuestFlow.ts`, scenario `quests`; see `ui-quests.md`).

### Screens (M2.1)
- Title: wordmark, version, then nothing offered until settings arrive (loading block or `AppErrorView`); a name field (prefilled once progress loads) and "Set up your studio" for a learner with no `firstRunCompletedAt`, otherwise Continue with a greeting and the role from the rules; environment chips (engine, sandbox, review, loop, editor) from `getEnvironmentStatus`.
- First-run (`#/first-run`, A244): step rail plus one panel per step (engine with toolchain check, saved with `updateSettings({ enginePath })` on confirm; sandbox folder with warnings; first full build with `components/BuildProgressView.tsx`, whose outcome is running, succeeded, failed (red), or cancelled (quiet, with Start again); editor once; done). Failures use `AppErrorView` with a retry; a failed build is explained by `lib/sandboxFailure.ts` for its context (first run or rebuild) with the compiler output behind a toggle.
- Studio: lead programmer card (portrait, role, XP bar, stats), today (due count, streak, next due), daily quest (three offers, choose one, chest), continue or up next, engine room and shipped titles (A247).
- World Map: region tabs per pack, a contract card per world (client portrait, brief, progress, test-out), stage nodes on a path that wraps into balanced rows to fit the card (`worldMap/StagePath.tsx` with `hooks/useElementWidth.ts` and `lib/pathRows.ts`, A390; it sets `data-measured` once its width is known, after which its rows stop regrouping on load, A980; `worldMap/StageNode.tsx`: locked dashed with the reason in a tooltip, open outline, in progress thick ring with a dot, passed solid with a check, rematch a warm glowing ring with a replay mark and the rematch share from the rules, boss larger), legend.
- Character: level and role, spree, streak with milestones, held items, skill tree, pattern card grid, attempt history.
- Codex: filter box, category select, term list, entry detail (short, long, aliases, where you meet it, review due, related terms, Epic docs, Drill me through `queueDrillItem`). No example section yet (A246).
- Settings: engine (pick another), sandbox (rebuild with progress and cancel), loop mode (fast disabled on macOS, A243), review provider with availability, Test Claude Code, API key (masked once stored), model id, reset progress behind a confirmation dialog.
- `lib/loopDescription.ts` is the only place that words the loop; on macOS it never says fast (A45, A243).
