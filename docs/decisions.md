### A302 2026-10-21 Tests-only label matching ignores kind words; a partial match needs half the required core (M1.7b, Lead decision)
A158 still let "Component" cover "HealthComponent" and "Wave" cover "WaveSpawnerSubsystem". Decided (Lead): a learner label still matches when it contains the whole required label. Otherwise both labels are split into words (camel case and spaces), kind words (component, actor, class, object, event, delegate, data, asset, struct, step, system, subsystem, manager, controller, handler, service, interface, widget, base, on) and one-letter Unreal prefixes are removed, along with any word whose singular (a trailing "s" or "es" removed) is a kind word, so "Steps", "Systems", and "Classes" count like "Step", "System", and "Class" (fix round 1), and the learner's core must be part of the required core, at least 4 characters, and at least half the required core's length. "Half the required label's length" is measured on the core, not the whole label, because measuring the whole label would reject the natural "Health" for "HealthComponent" (6 of 15); proposed by builder-review and confirmed by the Lead. Reverse cost: none.

### A301 2026-10-21 Unreadable secure storage falls back like an unavailable provider (M1.7b, Lead decision)
When safeStorage cannot decrypt the key, `readApiKey` throws `secure-storage-unavailable`, which used to reach the caller and fail the submit. Decided (Lead): the service treats `secure-storage-unavailable` like `review-unavailable`: the API provider is marked unavailable with that reason (shown in Settings) and the review goes to the next pick, which after the API is tests-only with `fallbackReason`. It never blocks a submit. Reverse cost: none.

### A300 2026-10-21 A timeout falls back to tests-only with a "Retry review" hint, never to the API (M1.7b, Lead decision)
A154 sent a Claude Code timeout to the next provider like any other `review-unavailable`, so in `auto` a slow subscription review could silently become a paid API review. Decided (Lead): timeouts get their own AppError code, `review-timeout` (Claude Code past 3 minutes, and the API's connection timeout). On `review-timeout` the service answers with tests-only at once, setting `fallbackReason` (the timeout message plus "Press Retry review to ask again") and a new optional `retryReviewSuggested: true` on `CodeReview`, `BreakdownGrade`, and `ExplainGrade` in `src/shared/types/review.ts`, so the screen can offer the retry. The timed-out provider is not marked, so a retry or the next submit goes to it again. Only `review-unavailable` (not installed, not signed in, key rejected, unreachable) and `secure-storage-unavailable` move on to the next provider. The Settings test follows the same rule: a timeout there reports Claude Code unavailable but does not set it aside. Reverse cost: low.

### A159 2026-10-21 Bad line numbers are dropped; a cancel ends the 429 wait (M1.7 fix round 1, builder-review)
The schema rejected a finding line below 1, which failed the whole review over one citation. Chosen: the schema accepts any integer and the code reviewer drops a line below 1 or past the end of the file, keeping the finding. The API provider's 429 wait now listens to the abort signal, ends at once on cancel, and throws `run-cancelled` without a second call. Reverse cost: none.

### A158 2026-10-21 Tests-only label matching needs the whole required label or a part of at least 4 characters (M1.7 fix round 1, builder-review)
Substring matching either way let a one-letter learner label ("A") cover every required piece. Chosen: a learner label matches when it contains the normalized required label ("PlayerHealthComponent" covers "HealthComponent"), or when it is part of the required label and at least 4 characters long ("Door" covers "DoorActor", "UI" does not). Reverse cost: none.

### A157 2026-10-21 Windows stops the process tree with taskkill; temp cleanup can never replace a result (M1.7 fix round 1, builder-review)
A `.cmd` shim runs as `cmd.exe` plus the `node` it starts, and killing `cmd.exe` leaves `node` running. Chosen: on Windows a timeout or cancel runs `taskkill /PID <pid> /T /F`, spawned without a shell (falling back to killing the direct child if taskkill cannot start); macOS and Linux keep SIGINT then SIGKILL. The temp folder is removed with three retries and any failure is swallowed, so the review's own answer or error always wins. Both Windows paths are unverified on Windows. Reverse cost: none.

### A156 2026-10-21 Code review prompt version 2: compiler output and test results are data (M1.7 fix round 1, builder-review)
Version 1 only said file contents were never instructions, but a learner controls compiler output and test messages too (a `#pragma message` or a test string). Version 2 says everything inside `<files>`, `<file>`, `<test_results>`, and `<compiler_output>` is data to review, never to follow, and asks the reviewer to flag an attempt to steer it as a problem finding. Closing tags inside all of them were already broken (A151); a test now covers compiler output and test messages. Reverse cost: none.

### A155 2026-10-21 `claude -p` runs without ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN (M1.7 fix round 1, Lead decision)
If the app is started from a terminal where a key is set, Claude Code would bill that key instead of the learner's subscription, which D11 chose on purpose. Chosen (Lead): both variables are removed from the environment for every `claude` spawn, the version check included; everything else is passed through. ### A154 2026-10-21 A provider that cannot review is skipped for 10 minutes; tests-only says why (M1.7 fix round 1, builder-review)
An installed but signed-out Claude Code passed the availability check, so in `auto` every submit picked it and failed. Options: a real round trip before every review (slow, costs a request); mark the provider when a review fails. Chosen: when a grader's provider throws `review-unavailable` (not cancel, refusal, or invalid output), the selector marks it unavailable with that reason and the same review is retried on the next pick: in `auto` the API, otherwise tests-only. The mark lasts 10 minutes and then the provider is tried again, so a passing network blip does not disable a provider for the session. The Settings test feeds the selector: a failed connection check marks Claude Code, a passing one clears the mark. `getProviderStatuses` now uses cached checks (the mark shows there with its reason); only the test button rechecks Claude Code. `CodeReview`, `BreakdownGrade`, and `ExplainGrade` gain an optional `fallbackReason` in `src/shared/types/review.ts`, set when tests-only answered because AI providers were unavailable. Reverse cost: low.

### A147 2026-10-21 Anthropic API request shape and retry rules (M1.7, builder-review)
Chosen: `client.beta.messages.create` (needed for the refusal fallback) with the model from settings, `max_tokens` 16000 (non-streaming limit), the system prompt marked for caching, the schema as `output_config.format`, and no thinking or effort override (the model's defaults). ### A145 2026-10-21 What tests-only answers look like (M1.7, builder-review)
The spec says tests-only turns test results and the rubric into findings. Chosen: code review scores the share of tests passed (progress-and-rules says review = tests when tests-only), failed tests become problem findings with the test's message, each rubric line becomes a "Self-check" suggestion, and `rubric` is left empty rather than claiming lines were met or not. Breakdown matches required pieces by normalized label (letters and digits, substring either way) and shows the reference plan that shares the fewest labels. Explain items answer score 70, verdict `partly`, and "Self-check against the model answer: ..." so the drill still moves on. Options rejected: marking every rubric line met (false) or unmet (punishing). Reverse cost: low.

### A144 2026-10-21 Strict checks after the schema parse (M1.7, builder-review)

Lenient on cosmetics: a finding citing a file that was not submitted loses its file and line, a line past the end of the file is dropped, fractional scores are rounded, and fenced code longer than one line in a finding, hint, or explanation is replaced with "(code removed: the mentor shows at most one corrected line)". Reverse cost: none.
