### A286 2026-10-21 Engine smoke builds the cmd.exe command line by hand for Build.bat (QA harness fix round 1, tester)
Found in review: passing `Build.bat` and its arguments to `cmd.exe /d /s /c` as separate arguments lets Node quote each one for a normal program, which cmd.exe then splits again at the first space, so the default `C:\Program Files\Epic Games\...` path breaks. Options: `shell: true` with pre-quoted arguments (what `NodeProcessRunner` does); build the line ourselves. Chosen: build it ourselves with the same quoting (each part in double quotes, inner quotes doubled, the whole line in one more pair) and spawn `cmd.exe` with `windowsVerbatimArguments: true`, which is exactly what Node's shell mode does, without importing app code into `tools/qa`. A timeout kills the tree with `taskkill /T /F`. Unit tested; unverified on a real Windows machine. Superseded by the Lead's rule that only `src/main/services/unreal/` spawns Unreal: this code stays until M1.3 merges, then the smoke switches to `SandboxProjectService`, `UnrealBuilder`, and `AutomationTestRunner` and `tools/qa/windowsCommandLine.ts` and its test are removed. Reverse cost: low.

### A429 2026-10-21 A corrupt `config.json` is set aside and settings start from the defaults (M0.2c fix round 1, builder-shell)

### A189 2026-10-21 IPC: `createSandbox`, `cancelRun`, and `pickSandboxFolder` answer now; `runQuest` and `rebuildSandbox` wait (builder-unreal, M1.2 and M1.3)

### A188 2026-10-21 Process trees: own process group plus SIGKILL on macOS, `taskkill /T /F` on Windows; only the quest test file gets a header comment (builder-unreal, M1.3)
Options for cancel: kill the root process only; kill the tree. Chosen: the tree. On macOS every build and test process starts in its own process group (`detached`) and cancel sends SIGKILL to the group, which reaches UBT, clang, and the editor's helpers; on Windows `taskkill /PID <id> /T /F`. A unit test with real processes proves the run resolves when the process exits although a grandchild still holds the output pipe, and that the group kill ends the grandchild. Fix round 1: once the root process has exited, Windows does not run `taskkill` (macOS still kills the group). `taskkill /T` finds the tree through the root's process id, which is gone after exit and may already have been reused by an unrelated program, so a late kill could end the wrong tree. Children that outlive the root on Windows are left alone (none were seen on the Mac apart from the storage daemon, which is meant to outlive the editor). Quitting the app cancels every running build and test first (`RunRegistry.cancelAll` on `before-quit`, waiting up to 5 s), so no UBT or editor is orphaned holding UBT's mutex. Header comment: the spec asks for a comment naming the quest; adding it to learner files would shift every compiler line number away from what the learner sees, so only the test file gets it. Reverse cost: low.

### A182 2026-10-21 On Windows the build runs `UnrealBuildTool.exe` directly instead of `Build.bat` (builder-unreal, M1.3)
Node refuses to spawn a `.bat` or `.cmd` without a shell (since the 2024 security fix), and a shell would bring back quoting problems. Chosen: UBT directly, same arguments (`DojoEditor Win64 Development -Project="..." -WaitMutex -Progress`). ## Decided during planning (2026-10-21)

### D01 App shell: Electron 44 + electron-vite 6
Options: Electron, Tauri 2. Chosen Electron: process spawning and log streaming are plain Node, one language end to end, the most reliable AI-generated code, no capability allow-lists. Startup is on par with Tauri; only installer size is worse. Source: `research/tooling-and-stack.md` section 1. Reverse cost: high after the pipeline is built.

### D02 Editor: Monaco via @monaco-editor/react
Options: Monaco, CodeMirror 6. Chosen Monaco: built-in C++ tokenizer, `registerHoverProvider` and `registerCompletionItemProvider` are exactly what the glossary needs. Bundled locally with the worker setup. Reverse cost: medium.

### D03 UI: React 19, TypeScript strict, Tailwind v4, shadcn/ui on radix-ui, Motion, lucide-react
One styling system, components copied into the repo, one animation library covering counters, flips, presence, layout. No chart library; XP bar and skill tree are inline SVG. TypeScript pinned to 5.9.x; try 7.x only if everything in the chain accepts it.

### D09 Unreal loop: fast loop over UE 5.8's built-in MCP server, headless loop as fallback
Verified against Epic's API docs: UE 5.8 ships `UAutomationTestToolset` (DiscoverTests, ListTests, RunTests, RunTestsByFilter, GetTestStatus, GetTestResults, StopTests) and `ULiveCodingToolset::CompileLiveCoding()` behind the editor's local MCP server at `http://127.0.0.1:8000/mcp`. The app calls these directly as an MCP client; no LLM in the loop. Live Coding does not pick up new UFUNCTION declarations or new classes, so the first build of a quest (or any header change to reflected types) goes through UnrealBuildTool; later iterations are seconds. For UE 5.4 to 5.7, the headless loop (Build.bat or Build.sh, then UnrealEditor-Cmd with `-ExecCmds="Automation RunTests ..."` and `-ReportExportPath`) is used. Both sit behind one `IRunner` interface.
